# Inference status

The reference generator supports greedy decoding (`temperature=0`), temperature sampling, top-k, nucleus top-p, min-p, repetition penalty, EOS, and stop-token sequences. `stream_generate` yields one token tensor per iteration, and the command line decodes the resulting sequence. Static batching is available for equal-length prompts through `novalm.serving.batching.batch_generate`; the API does not yet batch concurrent requests.

The model supports per-layer KV caching and keeps GQA caches at KV-head width. `benchmarks/kv_cache.py` checks cached/uncached greedy output equality and reports decode speed and KV bytes for the local device. The HTTP layer can stream generated pieces as SSE. `benchmarks/inference.py` reports TTFT and post-first-token throughput; its 4-token CPU smoke result in [`inference_cpu_smoke.json`](../experiments/reports/inference_cpu_smoke.json) is not representative of production serving. Quantization has CPU dynamic-INT8 and experimental packed weight-only INT4 paths. INT4 weights are dequantized on each forward, so the reference reduces stored state size but is slower in the tiny smoke benchmark. Neither path has a held-out language-quality measurement. The API does not yet provide static request batching or continuous batching. The generation and tokenizer-analysis CLIs force UTF-8 output for Windows consoles.
